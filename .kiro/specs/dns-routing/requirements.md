# DNS路由功能需求文档

## 简介

DNS路由功能允许用户根据域名规则将DNS查询路由到不同的上游DNS分组。用户可以导入预定义的域名规则列表，也可以自定义规则，实现灵活的DNS分流解析。

## 术语表

- **DNS路由 (DNS Routing)**: 根据规则将DNS查询分配到不同上游分组的机制
- **域名规则 (Domain Rule)**: 用于匹配域名的规则，支持精确匹配、通配符、正则表达式等
- **规则列表 (Rule List)**: 包含多个域名规则的集合，可从文件导入
- **上游分组 (Upstream Group)**: 在v10.1中实现的DNS服务器分组功能
- **路由规则 (Routing Rule)**: 将域名规则与上游分组关联的配置项
- **系统 (System)**: 指AdGuardHome DNS路由系统

## 需求

### 需求 1: 规则列表管理

**用户故事:** 作为系统管理员，我希望能够导入和管理域名规则列表，以便快速配置常用的DNS路由规则。

#### 验收标准

1. WHEN 用户访问DNS路由配置页面 THEN 系统应显示规则列表管理界面
2. WHEN 用户点击导入规则列表按钮 THEN 系统应提供文件上传和URL导入两种方式
3. WHEN 用户上传规则列表文件 THEN 系统应验证文件格式并显示导入结果
4. WHEN 用户提供规则列表URL THEN 系统应下载并解析规则列表
5. WHEN 规则列表导入成功 THEN 系统应显示规则数量和预览信息
6. WHEN 用户查看已导入的规则列表 THEN 系统应显示列表名称、规则数量、更新时间和状态
7. WHEN 用户删除规则列表 THEN 系统应提示确认并移除相关的路由规则

### 需求 2: 自定义规则配置

**用户故事:** 作为系统管理员，我希望能够创建和编辑自定义域名规则，以便满足特定的DNS路由需求。

#### 验收标准

1. WHEN 用户点击添加自定义规则按钮 THEN 系统应显示规则编辑表单
2. WHEN 用户输入域名规则 THEN 系统应支持精确匹配、通配符(*.example.com)和正则表达式格式
3. WHEN 用户选择上游分组 THEN 系统应显示所有可用的DNS分组列表
4. WHEN 用户保存自定义规则 THEN 系统应验证规则格式和分组有效性
5. WHEN 规则格式无效 THEN 系统应显示具体的错误信息和修正建议
6. WHEN 用户编辑现有规则 THEN 系统应加载当前配置并允许修改
7. WHEN 用户删除自定义规则 THEN 系统应提示确认并移除该规则

### 需求 3: 路由规则优先级管理

**用户故事:** 作为系统管理员，我希望能够设置规则的优先级，以便控制多个匹配规则的执行顺序。

#### 验收标准

1. WHEN 用户查看路由规则列表 THEN 系统应按优先级顺序显示所有规则
2. WHEN 用户拖拽规则项 THEN 系统应允许调整规则的优先级顺序
3. WHEN 用户设置规则优先级数值 THEN 系统应接受正整数并自动排序
4. WHEN 多个规则匹配同一域名 THEN 系统应使用优先级最高的规则
5. WHEN 规则优先级相同 THEN 系统应按照创建时间先后顺序处理
6. WHEN 用户保存优先级更改 THEN 系统应立即应用新的优先级配置

### 需求 4: 规则测试和验证

**用户故事:** 作为系统管理员，我希望能够测试域名规则的匹配效果，以便验证配置的正确性。

#### 验收标准

1. WHEN 用户在测试界面输入域名 THEN 系统应显示匹配的路由规则
2. WHEN 域名匹配到规则 THEN 系统应显示规则名称、匹配模式和目标上游分组
3. WHEN 域名未匹配任何规则 THEN 系统应提示使用默认上游配置
4. WHEN 用户测试多个域名 THEN 系统应批量显示测试结果
5. WHEN 规则配置发生变化 THEN 系统应允许重新测试验证

### 需求 5: 规则统计和监控

**用户故事:** 作为系统管理员，我希望能够查看规则的使用统计，以便了解DNS路由的实际效果。

#### 验收标准

1. WHEN 用户查看规则详情 THEN 系统应显示该规则的匹配次数
2. WHEN 用户查看统计时间范围 THEN 系统应支持最近24小时、7天、30天的统计
3. WHEN 规则被匹配使用 THEN 系统应实时更新统计计数
4. WHEN 用户查看热门域名 THEN 系统应显示最常匹配的域名列表
5. WHEN 用户导出统计数据 THEN 系统应提供CSV或JSON格式的导出功能

### 需求 6: 规则列表自动更新

**用户故事:** 作为系统管理员，我希望规则列表能够自动更新，以便保持规则的时效性。

#### 验收标准

1. WHEN 用户配置规则列表URL THEN 系统应提供自动更新选项
2. WHEN 用户启用自动更新 THEN 系统应允许设置更新间隔（小时/天）
3. WHEN 到达更新时间 THEN 系统应自动下载并更新规则列表
4. WHEN 自动更新失败 THEN 系统应记录错误日志并保留旧规则
5. WHEN 规则列表更新成功 THEN 系统应显示更新时间和变更摘要
6. WHEN 用户手动触发更新 THEN 系统应立即执行更新操作

### 需求 7: UI界面设计

**用户故事:** 作为系统管理员，我希望DNS路由配置界面清晰易用，以便快速完成配置。

#### 验收标准

1. WHEN 用户访问DNS设置 THEN 系统应在DNS配置页面显示"DNS路由"标签页
2. WHEN 用户查看路由规则 THEN 系统应使用表格形式展示规则列表
3. WHEN 规则列表较长 THEN 系统应提供分页和搜索功能
4. WHEN 用户操作规则 THEN 系统应提供添加、编辑、删除、启用/禁用的快捷按钮
5. WHEN 用户配置复杂规则 THEN 系统应提供表单验证和实时反馈
6. WHEN 用户保存配置 THEN 系统应显示保存状态和成功/失败提示
7. WHEN 界面加载数据 THEN 系统应显示加载指示器避免用户困惑

### 需求 8: 规则导入格式支持

**用户故事:** 作为系统管理员，我希望系统支持多种规则文件格式，以便兼容不同来源的规则列表。

#### 验收标准

1. WHEN 用户导入规则文件 THEN 系统应支持纯文本格式（每行一个域名）
2. WHEN 用户导入规则文件 THEN 系统应支持带注释的格式（#开头为注释）
3. WHEN 用户导入规则文件 THEN 系统应支持dnsmasq格式的规则
4. WHEN 用户导入规则文件 THEN 系统应支持AdGuard格式的规则
5. WHEN 规则文件包含无效行 THEN 系统应跳过无效行并记录警告
6. WHEN 规则文件编码不是UTF-8 THEN 系统应尝试自动检测编码

### 需求 9: 规则冲突检测

**用户故事:** 作为系统管理员，我希望系统能够检测规则冲突，以便避免配置错误。

#### 验收标准

1. WHEN 用户添加新规则 THEN 系统应检查是否与现有规则冲突
2. WHEN 检测到完全相同的规则 THEN 系统应提示重复并阻止添加
3. WHEN 检测到规则覆盖关系 THEN 系统应警告用户并说明优先级影响
4. WHEN 用户确认添加冲突规则 THEN 系统应允许用户明确确认后继续
5. WHEN 用户查看规则列表 THEN 系统应标记存在冲突的规则

### 需求 10: 规则备份和恢复

**用户故事:** 作为系统管理员，我希望能够备份和恢复DNS路由配置，以便在需要时快速恢复设置。

#### 验收标准

1. WHEN 用户点击导出配置 THEN 系统应生成包含所有路由规则的配置文件
2. WHEN 用户导入配置文件 THEN 系统应验证文件格式并显示预览
3. WHEN 导入配置与现有配置冲突 THEN 系统应提供合并或替换选项
4. WHEN 用户确认导入 THEN 系统应应用新配置并备份旧配置
5. WHEN 导入失败 THEN 系统应保持原有配置不变并显示错误信息
